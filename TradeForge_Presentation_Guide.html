1. Executive Summary & Architecture

TradeForge is an academic stock trading simulation built using Java 11, Java Swing, MVC Architecture, JDBC, and MySQL. The application demonstrates exactly 10 Gang of Four (GoF) design patterns working in an integrated, authentic desktop workflow.

2. Complete Design Patterns Mapping Table

# Pattern Type Primary Classes Concrete Responsibility in TradeForge
1 Singleton Creational DatabaseConnection Provides a shared, thread-safe JDBC connection manager across the application lifecycle to avoid memory leaks.
2 Factory Creational TransactionFactory, BuyTransaction, SellTransaction Instantiates BUY or SELL transaction objects to calculate 2% brokerage charges and net totals dynamically.
3 Proxy Structural TradingServiceProxy, RealTradingService Protection proxy: verifies user authentication and ownership before delegating trade execution.
4 Chain of Resp. Behavioral Tier1AgentHandler, Tier2AgentHandler, Tier3AgentHandler Routes orders to broker agents based on quantity: 1–500 (Agent 1), 501–700 (Agent 2), >700 (Agent 3). Plus a validation chain.
5 Observer Behavioral StockTradingSubject, UserNotificationObserver Broadcasts trade completion events in real time to update the dashboard's top notification banner.
6 Builder Creational TradeBuilder Fluent, step-by-step assembly of TradingRequest objects with strict field validation before execution.
7 Mediator Behavioral TradingMediator Central hub that coordinates the Controller, Proxy, Chains, Template Method, DAOs, and Observers, achieving loose coupling.
8 Template Method Behavioral TradingTemplate, BuyTradingWorkflow, SellTradingWorkflow Enforces an invariant 5-step trade sequence (validate → check → execute → save → notify) with customized hooks inside an ACID transaction.
9 Memento Behavioral TradeMemento, TradeCaretaker Captures and restores UI trade draft form values (Save Draft and Undo/Restore) without altering database state.
10 Prototype Creational TradePrototype, TradingRequest Deep-clones trade requests (Duplicate Trade) to create an independent editable draft without immediate database writes.

4. Top Viva Questions & Model Answers

Q1: Why did you use the Mediator pattern instead of having the Controller coordinate everything?

Answer: In a trading system, if the Controller directly invoked the Proxy, Builder, Factory, DAOs, Chain handlers, and Observers, it would become an overly complex "God Object" with high coupling. The TradingMediator centralizes this coordination so the Controller only interacts with a single, high-level interface.

Q2: How does your Proxy Pattern provide protection?

Answer: TradingServiceProxy implements TradingService and acts as a security barrier. It checks: (1) user is authenticated (userId > 0), (2) caller owns the request, and (3) request is not null. It rejects invalid requests with a SecurityException before any database queries execute.

Q3: What is the difference between Prototype and Memento in your app?

Answer: Prototype creates a new, independent clone of an object with identical values for cloning or duplication. Memento captures an internal state snapshot of an existing object so it can be restored to that exact previous state later via Undo.

Q4: Why is the template method in TradingTemplate declared final?

Answer: Because the Template Method pattern requires the core algorithm skeleton (validate → check availability → execute operation → save transaction → notify observers) to remain invariant. Declaring processTrade(...) as final prevents subclasses from altering the execution order, while allowing them to customize hook steps.

Q5: How does your system maintain database consistency during trades?

Answer: Inside RealTradingService, we disable auto-commit (connection.setAutoCommit(false)). All four database mutations—user balance update, stock inventory update, portfolio holding update, and transaction record insertion—execute in a single JDBC transaction. If any error occurs, connection.rollback() is triggered, preserving ACID guarantees.

Q6: What are the exact Chain of Responsibility thresholds for Agent Assignment?

Answer:

  • 1 to 500 stocks: Agent 1 (Rahul Sharma — Tier 1)
  • 501 to 700 stocks: Agent 2 (Priya Patel — Tier 2)
  • More than 700 stocks: Agent 3 (Amit Verma — Tier 3)
Each tier handler checks the condition; if it falls outside its range, it delegates to the next handler in the chain.
